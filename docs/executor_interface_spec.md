# Executor ↔ System Interface Specification

This document specifies the interface between `executor` and the system-under-test (SUT), focusing on:

- executor instruction stream (`instr_copyin`, `instr_copyout`, syscall records, etc.),
- argument encodings (`arg_const`, `arg_addr32`, `arg_data`, ...),
- syscall execution contract,
- and how to adapt this boundary for remote forwarding to a server.

Primary sources:

- `executor/executor.cc`
- `executor/executor_runner.h`
- `executor/executor_xtratum.h`
- `prog/encodingexec.go`
- `executor/defs.h`

---

## 1. Data flow overview

At runtime, the executor consumes a serialized program (`input_data`) and executes an instruction stream:

1. Parse instruction (`read_input`, varint + zigzag decode).
2. Apply memory prep operations (`instr_copyin`, checksums, etc.).
3. Execute syscall instruction (`call_num`, args).
4. Optionally read back values (`instr_copyout`) for later `arg_result` references.
5. Emit per-call result/coverage output.

Program encoding is generated by `prog.SerializeForExec()` in `prog/encodingexec.go`.

---

## 2. Instruction set (top-level entries)

Values are `uint64` in stream:

- `instr_eof = -1`
- `instr_copyin = -2`
- `instr_copyout = -3`
- `instr_setprops = -4`
- any other non-negative value: syscall ID (`call_num` index into `syscalls[]`)

### 2.1 `instr_eof`

**Brief**: End-of-program marker.

**Inputs**:

- none (just opcode)

**Expected outputs**:

- executor stops parsing this program.
- no direct SUT side effect.

---

### 2.2 `instr_copyin`

**Brief**: Write prepared data into executor data memory (`SYZ_DATA_OFFSET + addr`).

**Inputs**:

- `addr` (`uint64` offset; actual address = `addr + SYZ_DATA_OFFSET`)
- `typ` (`arg_*` selector)
- type-specific payload (see section 3)

**Expected outputs**:

- memory write side effect in executor argument memory.
- this memory later becomes syscall input (pointer targets).
- no direct return value in stream.

---

### 2.3 `instr_copyout`

**Brief**: Declare extraction of memory value after a syscall completes.

**Inputs**:

- `index` (result slot, `< kMaxCommands`)
- `addr` (offset; interpreted as `addr + SYZ_DATA_OFFSET`)
- `size` (`1|2|4|8`)

**Expected outputs**:

- deferred action: when associated call completes, executor loads value from `addr`.
- on success, stores value to `results[index]` (`executed=true, val=<loaded>`).
- this value can be consumed by future `arg_result`.

---

### 2.4 `instr_setprops`

**Brief**: Set execution properties for the *next* syscall.

**Inputs** (from `call_props_t` / `read_call_props_t`):

- `fail_nth` (`int`): fault-inject nth operation.
- `async` (`bool`): do not synchronously wait in threaded mode.
- `rerun` (`int`): extra reruns after first execution.

**Expected outputs**:

- executor updates pending call behavior.
- no direct syscall/memory output itself.

---

### 2.5 Syscall instruction (`call_num >= 0`)

**Brief**: Execute one syscall (or pseudo-syscall callback) with up to 9 args.

**Inputs**:

- `call_num` (index into generated `syscalls[]` table)
- `copyout_index` (`ExecNoCopyout` or result index)
- `num_args` (`<= kMaxArgs`)
- `args[]` (each encoded as `arg_*`, section 3)
- current `call_props_t` (possibly set by preceding `instr_setprops`)

**Expected outputs**:

- system call side effect on SUT.
- primary result: `res` (`intptr_t`) and `errno`.
- if `copyout_index != no_copyout`: `results[copyout_index]=res`.
- deferred `instr_copyout` records may populate additional `results[]` entries.
- output record (`CallInfoRaw`) includes executed/finished/blocked/fault flags, error, and optional signal/cover/comparisons.

---

## 3. Argument encodings (`arg_*`)

Argument type tags:

- `arg_const = 0`
- `arg_addr32 = 1`
- `arg_addr64 = 2`
- `arg_result = 3`
- `arg_data = 4`
- `arg_csum = 5`

### 3.1 `arg_const`

**Brief**: Immediate scalar constant with size/format/bitfield metadata.

**Inputs**:

- `meta` bit layout:
  - bits `0..7`: size (bytes)
  - bits `8..15`: binary format
  - bits `16..23`: bitfield offset
  - bits `24..31`: bitfield length
  - bits `32..63`: pid stride
- `val`

**Expected outputs**:

- for syscall args: concrete integer value (native or big-endian adjusted).
- for `instr_copyin`: written to target memory location (with optional bitfield update/string formatting).

---

### 3.2 `arg_addr32`

**Brief**: 32-bit pointer/address value based on executor data segment.

**Inputs**:

- `addr_offset`

**Expected outputs**:

- effective value `addr_offset + SYZ_DATA_OFFSET`.
- for `instr_copyin`: value is written as `uint32`.
- for syscall args: passed as argument value.

---

### 3.3 `arg_addr64`

**Brief**: 64-bit pointer/address value based on executor data segment.

**Inputs**:

- `addr_offset`

**Expected outputs**:

- effective value `addr_offset + SYZ_DATA_OFFSET`.
- for `instr_copyin`: value is written as `uint64`.
- for syscall args: passed as argument value.

---

### 3.4 `arg_result`

**Brief**: Value derived from previous result slot (`results[idx]`) with arithmetic.

**Inputs**:

- `meta` (size + format; for syscall args only native format accepted)
- `idx`
- `op_div`
- `op_add`
- `fallback` (default if `results[idx].executed==false`)

**Expected outputs**:

- value = `results[idx].val` if available, else `fallback`.
- if available: apply `if op_div!=0 => value/=op_div`, then `value += op_add`.
- used as syscall arg or copyin payload.

---

### 3.5 `arg_data`

**Brief**: Raw byte blob copied to memory.

**Inputs**:

- `size_flags` (high bit marks readability, masked out in executor)
- `data[size]`

**Expected outputs**:

- bytes copied into destination address during `instr_copyin`.
- no scalar syscall argument value form (this tag is used in copyin path).

---

### 3.6 `arg_csum`

**Brief**: Runtime checksum calculation and writeback.

**Inputs**:

- `size` (currently must be `2` for inet checksum)
- `csum_kind` (`arg_csum_inet=0`)
- `chunks_num`
- chunks:
  - `arg_csum_chunk_data=0`: `(addr,size)` source bytes from data memory
  - `arg_csum_chunk_const=1`: `(value,size)` constant bytes (`size` in `{2,4,8}`)

**Expected outputs**:

- computes checksum and writes it to destination address (`instr_copyin` target).
- for inet checksum: 16-bit result written using native binary format.

---

## 4. Binary formats (used by `arg_const` / copyin)

- `binary_format_native = 0`
- `binary_format_bigendian = 1`
- `binary_format_strdec = 2` (20-byte zero-padded decimal string)
- `binary_format_strhex = 3` (18-byte `0x` + 16 hex digits)
- `binary_format_stroct = 4` (23-byte octal string)

**Expected outputs**:

- native/bigendian: integer write with optional bitfield insertion.
- string formats: textual rendering copied to destination bytes.

---

## 5. Syscall execution contract

### 5.1 Generic executor contract

Executor side function contract:

- `execute_syscall(const call_t* c, intptr_t a[kMaxArgs]) -> intptr_t`
- `errno` is side-channel output captured immediately after return.

`call_t` includes:

- `name`
- `sys_nr`
- `attrs` (`call_attrs_t`)
- `call` (optional function pointer for pseudo/user-space syscall handler)

Execution rules:

- if `c->call != nullptr`: call that function pointer.
- else: OS-specific syscall path (native syscall, platform shim, or proxy).

Per-call output fields (expected):

- return value (`res`)
- error (`errno` or synthesized `EINVAL` in some edge cases)
- flags (`Executed`, `Finished`, `Blocked`, `FaultInjected`, ...)
- optional feedback vectors (`signal`, `cover`, `comps`)

---

### 5.2 Xtratum-specific forwarding hook already present

`executor_xtratum.h` defines a weak transport hook:

- `xtratum_proxy_call(int32_t sys_nr, intptr_t a0..a5, intptr_t* ret, int* err_no) -> int`

Semantics:

- return `0`: transport success, outputs in `*ret`, `*err_no`.
- non-zero: transport/protocol failure (`errno=EIO`, syscall result forced to `-1`).
- missing hook: `errno=ENOSYS`, result `-1`.

This is already a minimal syscall-forwarding ABI.

## 6. Runner/executor control plane (context)

Though not syscall-level, these frames are required to run programs:

- `handshake_req`: environment flags, kernel bitness, proc id, timeouts, sandbox arg.
- `execute_req`: request id/type, execution flags, all-call/all-extra signal settings.
- `reply_execute(status)`: completion status for process-level loop.

These define execution mode but do **not** directly represent SUT side-effect operations.

---

## 7. Forwarding-oriented decomposition

For remote execution, split interface into:

1. **State-prep operations** (must be mirrored remotely):
   - `instr_copyin` (`arg_const|arg_addr32|arg_addr64|arg_result|arg_data|arg_csum`)
2. **SUT side-effect operation**:
   - syscall instruction (`call_num` + resolved args)
3. **State-readback operations**:
   - `instr_copyout`

### Recommended remote RPC surface

A practical server API (conceptual):

- `RemoteCopyIn(addr, encoding, payload) -> status`
- `RemoteSyscall(sys_nr, args[0..5], attrs/props) -> {ret, errno, aux}`
- `RemoteCopyOut(addr, size) -> {ok, value}`
- `RemoteResetProgramState(procid/request_id)` (optional lifecycle)

Where `aux` can optionally carry coverage/comparisons if moved remote.

---

## 8. Entry-by-entry forwarding notes

- `instr_copyin`: must be forwarded if remote side owns syscall-visible memory.
- `instr_copyout`: must be forwarded/read remotely if result values come from remote memory.
- `instr_setprops`: should be forwarded if server performs fault injection/rerun/async behavior.
- syscall instruction: always forwarded in remote mode.
- `instr_eof`: local parser control only.

---

## 9. Invariants and limits to preserve

- `kMaxInput = 4 MiB`
- `kMaxCommands = 1000` (result slots)
- `kMaxArgs = 9` in executor core, but many syscall backends consume first 6 register args.
- stream integers are varint-encoded signed values (zigzag decode in executor).
- address values are interpreted relative to `SYZ_DATA_OFFSET`.
